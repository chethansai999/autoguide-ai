## Local smoke check — October 10, 2026

Reproduction: start the API/UI using README's local-testing commands, inspect `/ready`, and ask the sample questions there. This was an ad hoc smoke check against the configured real Gemini provider, not an evaluation on either the DEV or held-out TEST split. No held-out questions were read, and no mock answer-quality numbers are reported.

- The local store contained 17,313 vehicle rows and 114 fixed chunks from five supplied reference PDFs. AutoGuide, Wikipedia and FuelEconomy HTML collections were empty.
- Real Gemini responses cited the loaded NHTSA record for the 2020 Toyota Camry rating, correctly described backup-camera availability as unreported in that record, and cited the supplied IIHS small-overlap crash protocol. These checks establish individual working paths, not corpus-wide factual accuracy.
- Missing vehicle details produced clarification; empty website scopes produced `no_evidence`; forecasts and input-injection attempts were refused. Browser feedback displayed “Feedback saved. Thank you.”
- NHTSA recall evidence was found, but Gemini returned HTTP 429 quota errors during recall generation. Later provider calls also returned 429. Live generation therefore remains externally limited; quota errors are not disguised as connection failures or mock successes.
- Testing overlapping UI/API requests exposed SQLite writer locking during a slow new-chat turn. The orchestrator now loads/detaches state before retrieval/generation and saves session/messages/trace atomically afterward. Recall caching finishes independently before answer generation. Regression checks cover another caller saving during generation for both new and existing conversations.
- Verification: `.venv/bin/python -m pytest -q` → **182 passed, 2 xfailed**. The expected failures remain WP-03 structure chunking. A post-fix live overlap test saved a separate greeting in 0.01 seconds while the slow call completed with a provider quota error, without a database-lock exception. This timing is an observed smoke check, not a throughput benchmark.
- Browser review covered desktop/tablet/mobile viewports. Responsive topic cards still become too narrow on tablet with the sidebar open; the mobile sidebar needs closing to see the content. No committed screenshot baseline exists, so visual regression is inconclusive. Basic DOM checks also found missing image alternatives/landmarks; this was not a complete accessibility audit.

## Local generation integration (WP-12, October 11, 2026)

The owner requested local operation after Gemini quota exhaustion, OpenAI exhausted credits and a Hugging Face hosted-generation HTTP 402. The supplied Hugging Face token authenticated successfully; authentication does not establish hosted credit availability. Credentials remain only in ignored `.env` and are not included in the public repository.

`LLM_PROVIDER=local` now selects the optional MLX provider behind the existing `LLMClient` interface. A previously cached `meta-llama/Meta-Llama-3.1-8B-Instruct` snapshot was converted offline with 4-bit weights, group size 64, to roughly 4.2 GiB under ignored `data/models/llama-3.1-8b-4bit`. This is quantization, not corpus training. The machine has Apple GPU support and 18 GiB RAM. The tested optional runtime is `mlx-lm==0.32.0` with MLX 0.32.3, Python 3.12. Requests reuse model weights within one API process and serialize GPU access; Streamlit calls that API over HTTP. The provider loads only an existing local path, with remote code disabled, and rejects context overflow without dropping evidence.

**Observed failure and fix:** the first live local answer for a backup camera turned the CSV value `not reported` into a claim of absence. Questions containing an unknown requested feature now render the structured fields directly and explain that availability is unknown, with the same citation and quotation checks. Traces identify this path as `structured-data` / `none`, with no model tokens. Explicit `not available` remains a distinct value. This applies consistently across providers; it does not hide hosted provider authentication or quota errors.

**Actual local smoke observations:** `/ready` returned HTTP 200 with provider `local`, demo false, 17,313 vehicle records and 114 indexed reference passages. The rating question "What is the overall NHTSA star rating of the 2020 Toyota Camry?" returned 5 stars with a NHTSA citation: 11.99 s after restarting the API, then 4.00 s for the next independent request, with 901 prompt tokens and 22 output tokens. In the initial run the IIHS small-overlap speed question returned 64.4 ± 1 km/h with the supplied protocol citation in 18.78 s (3,415 prompt tokens, 26 output tokens). The corrected backup-camera check took 0.26 s and preserved unknown availability without a model call. Missing vehicle details asked for clarification, prediction and injection requests were refused, and a history question refused with `no_evidence` because live website collection is still skipped. The real browser rendered the local model status and corrected answer with its working NHTSA citation link.

Timings vary with machine load, prompt length and initial model loading. API usage cost is zero for local inference; this excludes hardware/electricity. These are individual smoke observations, not formal DEV/test evaluation scores or a production-readiness claim. No held-out questions were inspected or run. Live recalls still require network access and were not rechecked in this local-model smoke run. Formal real-provider DEV evaluation remains required for quality claims.

**Offline regression validation:** `python -m pytest -q` passed with 197 tests and the two existing WP-03 expected failures. New simulated-runtime checks cover lazy provider registration, system/history/sampler wiring, shared weights, missing/sharded artifacts, context overflow, generation errors, readiness without heavy imports, UI mode and unknown-versus-absent feature handling. These counts describe software tests, not mock model quality.
